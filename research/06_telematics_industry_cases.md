# テーマ6：車両データを使った事故予防・安全運転支援の産業事例

- 調査日：2026-11-01
- 調査方法：WebSearch / WebFetch によるオープンソース調査（検索結果または fetch で実在を確認した URL のみ掲載）
- テーマのゴール：車両データ（CAN / OBD / コネクテッドカーデータ）を使った事故予防・安全運転支援の産業事例（テレマティクス保険、フリート管理、コネクテッドサービス、商用車安全）を集め、ビジネスモデル・使用データ・効果（事故削減率など）・技術アーキテクチャを整理する。最終目的である「CAN データだけを使った有人運転車の危険予兆検知・警告」に転用できる知見を抜き出す。

---

## 1. エグゼクティブサマリー

1. 産業界で実用化されている運転リスク指標は、ほぼ全社で「急加速・急減速（急ブレーキ）・急旋回（横G）・速度超過・深夜走行・走行距離」の6系統に集約される。いずれも CAN（車速・ブレーキ・アクセル・操舵角）か加速度センサーから算出でき、カメラを使わなくても再現できる。
2. 閾値を公開している例は限られる。Tesla Safety Score（急ブレーキ 0.3g 超、急旋回 0.4g 超）、Geotab（車格別に急ブレーキ −0.47〜−0.61g）、Progressive Snapshot（急加速 7mph/s 超、深夜0〜4時）などである。
3. 日本では、トヨタとあいおいニッセイ同和損保の「タフ・つながるクルマの保険」が DCM 経由の CAN 系データ（アクセル・ブレーキ・ステアリング・シフト・ウインカー等）を使い、事故頻度が約3割低いと公表した（2019年）。同社はテレマティクス保険全体でも事故頻度 ▲18% を公表している（2023年）。
4. 海外では、Allstate Drivewise の利用者は重大事故が25%少ない（2024年）、CMT のフィードバックで脇見（スマホ操作）が25〜35%減ったとされる。ただし、いずれも自己選択バイアスを含む自社分析である。
5. フリート領域では Samsara（30か月で事故率 −73%）、Motive（−80%）、Lytx（Kroger で −50%）などが大きな削減率を掲げる。これらは AI ドラレコ（映像）と車内警告・コーチングを組み合わせた効果であり、CAN 単独の効果ではない。
6. 第三者研究では、FMCSA が資金を出した VTTI の研究（危険イベント −37% / −52.2%）や、Marketing Science 誌の UBI 研究（急ブレーキ −21%）がある。共通する結論は、効果の源泉が「計測とフィードバック（コーチング）の組合せ」にあるという点である。
7. 規制面では、米 FTC が GM・OnStar に運転データの第三者提供を5年間禁止する命令を確定させた（2026年1月）。EU では EDPB ガイドライン 01/2020 と EU Data Act（2025年9月適用）が同意とデータアクセス権を求めている。CAN データだけの設計でも、位置情報や個人識別子と結び付けば個人データとして扱われる前提で設計する必要がある。
8. 【推察】産業事例の多くは「事後スコアリング（月次・トリップ単位）」にとどまる。本プロジェクトが目指すリアルタイムの予兆検知（秒〜分単位の警告）は、Progressive のプラグイン機器のビープ音や Samsara・Motive の車内警告に近い。ただし CAN だけで同等の精度を出した公開事例は見当たらず、差別化の余地がある。

### 3.2 指標の有効性を示す第三者研究

- Marketing Science（2019）の UBI 研究では、UBI 加入者の1日平均の急ブレーキ回数が6か月後に21%減った。走行距離は減っておらず、若年層と女性で改善が大きかった。急ブレーキは保険会社が「行動変容の主要 KPI」として扱っている [22]。
- NJIT の研究は、コネクテッドカーのテレマティクスから得た急ブレーキ件数を州間高速道路区間の事故の代替指標として評価した。急ブレーキが1件増えるごとに期待事故件数が約1%増え、統計的に有意な正の関係があった [24]。
- TU Delft の Driessen ら（2023）は、トラックドライバーのデータで損傷事故・違反・燃費を予測した。先行研究として、Ma らの研究（503人、13万トリップ超）が「距離あたり急ブレーキ」と速度超過で事故率を予測できたことを引用している [25]。
- 【推察】急ブレーキの頻度（距離あたり・時間あたり）は事故リスクと相関するという点で、産業界と学術の見解はおおむね一致している。ただし、それは「事後に集計した頻度」としての指標である。単発イベントの直前を予兆として検知できるかは別の問題で、検証が必要である。

| A. OEM 純正 DCM（車載通信機） | トヨタ DCM、Honda CONNECT、Tesla、GM OnStar | CAN 上の全信号（アクセル、ブレーキ、操舵、シフト、ウインカー、ADAS 状態）[1] | 情報が最も豊富で精度が高い。後付け機器が不要 | OEM ごとに仕様が閉じている。データ提供には OEM との契約と利用者の同意が必要 |

### 4.2 標準

- **SAE J1939**：大型車向けの CAN 上位プロトコルで、通常 250kbit/s（500k にも対応）、29ビット拡張 ID を使う。ID は優先度3ビット、PGN 18ビット、送信元アドレス8ビットで構成され、信号は SPN（19ビット）で定義される。主な文書は J1939/71（車両アプリ層）、J1939/73（診断）、J1939-22（CAN FD 対応）である [30]。
- **FMS-Standard**：欧州のトラック・バスメーカーが合意した、J1939 のサブセットを外部へ出すゲートウェイ仕様。2002年に v1.0、2012年にバス・トラック統合、2017年に v4.0（クルーズ状態を追加）。車速（車輪速・タコグラフ）、ブレーキ・クラッチ SW、燃料消費量、燃料残量などを出す。コネクタは標準化されていない [29]。
- **OBD-II**：排ガス診断用の標準 PID（車速、回転数等）。安全指標に必要な操舵角・ブレーキ圧は標準外である。
- **クラウド連携**：OEM クラウドから第三者へ API で提供する形（High Mobility 型 [16]）と、テレマ機器ベンダーのクラウド（Samsara・Geotab 型）がある。保険用途では、スコアのみを提供する形（トヨタ → あいおいニッセイ同和損保）と生データを提供する形がある。

### 4.3 典型的な処理パイプライン【推察を含む】

```
[車両 CAN/J1939] → [エッジ：DCM/ゲートウェイ/ドングル]
      │  イベント検知（閾値超過：急減速 g、横 g 等）※リアルタイム警告はここで行う（Progressive のビープ音、Samsara の車内警告）
      ▼
[セルラー通信] → [クラウド：トリップ単位の集計・正規化（距離・時間あたり頻度）]
      ▼
[スコアリング：重み付け or 予測衝突頻度モデル（Tesla）／保険数理モデル（CMT）]
      ▼
[アウトプット：保険料割引／ドライバーへのフィードバック／管理者ダッシュボード／コーチング]
```

- 【推察】産業事例の多くはエッジで閾値判定をし、クラウドで集計とスコア化をする二層構成である。本プロジェクトのような秒単位の予兆警告にはエッジ側での推論が必須になる。

## 5. ビジネス・規制上の論点

### 5.1 ビジネスモデル

| モデル | 収益源 | 事例 |
|---|---|---|
| UBI / PHYD 保険 | 保険料（安全なドライバーを選別し、損害率を改善） | J1〜J4、G1〜G2、O1 |
| B2B2C スコアリング基盤 | 保険会社からのライセンス料・従量課金 | CMT [10] |
| フリート SaaS | 車両あたりの月額サブスクリプション | Samsara、Motive、Geotab、Lytx |
| メーカー純正コネクテッド | 新車販売時の付加価値、特約手数料、データ提供料 | トヨタ、ホンダ、ふそう、いすゞ、日野 |
| データマーケットプレイス | データ販売 | Wejo（破綻）[26]、High Mobility [16] |

- 【推察】Wejo の破綻は、「車両データを集めて第三者に売る」ことを単独で事業にする難しさを示している。データ量に対して収益化の速度が追いつかなかった。安全支援は、保険やフリート SaaS など支払い主体が明確な垂直領域で成立している。

### 5.2 効果の解釈上の注意

- 公表された削減率の多くは**自己選択バイアス**（安全なドライバーほど加入する）と**前後比較**（対照群なし）の影響を受ける。Allstate の25%は加入者と非加入者の比較 [9]、Samsara の73%は自社顧客の時系列比較 [11]、トヨタ系の約3割は商品間の比較 [1] である。
- 因果効果に最も近いのは、ベースライン（警告オフ）と介入期間を比べた VTTI・FMCSA の研究（危険イベント −52.2% / −37%）[23] と、加入前後の同一ドライバーを追跡した UBI 研究（急ブレーキ −21%）[22] である。
- フリート各社の数値は AI ドラレコの効果を含むため、**CAN 単独の効果は分離されていない**。

### 5.3 プライバシー・データ保護

## 6. 課題・ギャップと次のアクション提案

### 6.1 課題・ギャップ

1. **リアルタイム予兆検知の公開事例が乏しい**：産業事例はほぼ事後スコアリングである。リアルタイム警告の事例もカメラ依存か、単純な閾値ビープ（Progressive）にとどまる。
2. **CAN 単独の効果検証がない**：フリートの大きな削減率は AI ドラレコとコーチング込みの数値で、CAN 由来指標だけの寄与は不明である。
3. **閾値が車格・車種で大きく異なる**：Geotab の例では、急ブレーキ閾値が乗用車 −0.61g から大型 −0.47g まで幅がある [14]。固定閾値の流用は危険である。
4. **脇見・眠気は CAN で直接計測できない**：CMT・Allstate が最重要視するスマホ脇見 [9][10] は CAN では計測できず、代替指標が必要である。
5. **日本のデジタコ・運行管理の閾値仕様が非公開**：トランストロン、デンソー、矢崎などの急減速判定基準は、公開資料では確認できなかった（メーカー間で評価項目に差があるという学術資料はある）。

### 6.2 次のアクション提案

1. **閾値のベースライン設定**：Tesla（0.3g / 0.4g）と Geotab（車格別 g）の公開閾値を初期値とする。自社の CAN データで発生頻度の分布を取り、車種・速度帯ごとに再校正する（スキルの features.py の急加速・急減速フラグとも照合する）。
2. **「頻度指標」と「予兆指標」の二層化**：距離あたりの急ブレーキ頻度は事故リスクと相関するという第三者研究 [22][24][25] がある。これを長期のリスク層別に使い、別途、TTC・THW・操舵の乱れなど秒単位の予兆指標を CAN（ACC レーダー信号を含む）から作って検証する。
3. **脇見・漫然運転の CAN 代替指標の検討**：操舵エントロピー、微修正の欠如、アクセルの一定保持時間、車線内ふらつき（LDA 信号があれば利用）など、カメラを使わない推定手法の文献調査（テーマ横断）と特徴量化を進める。
4. **効果検証デザインの事前設計**：VTTI 方式（ベースライン期は警告オフ、介入期は警告オン）[23] で、警告の効果を危険イベント率の変化として測る計画を作る。自己選択バイアスを避けるため、同一ドライバーの前後比較か無作為化を採用する。
5. **プライバシー・バイ・デザインの方針策定**：エッジで推論し外部送信は統計値のみ、VIN と位置情報は分離、同意取得のフローを用意する。EDPB ガイドライン [18]、FTC の GM 命令 [19]、EU Data Act [35] を要件に落とし込み、国内法の該当性は法務で確認する。
